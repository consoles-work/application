The basics

Four panels. Zero chaos.

Tree, terminal, wiki and AI — everything a developer with many projects needs, organised the way your head works.

Project tree

Workspace → project → console. Icons and colours, drag-and-drop between projects, search, and recent consoles at the bottom.

Real terminals

Full PTY sessions in bash, zsh, fish or PowerShell. Local or SSH with a key, passphrase or password — startup commands run by themselves.

Wiki next to the shell

Notes for every workspace, project and console: code blocks, checklists, tags and full-text search.

AI assistant

OpenAI, Anthropic, local Ollama or your Claude Code subscription. Select terminal output — it becomes the context.

What's new

Grown up since the first beta

Quick commands

Buttons for the commands you type every day

Every console gets its own buttons under the terminal: restart a service, tail the logs, roll out a release. One click sends the command and presses Enter.

  • Groups: buttons live in labelled boxes — Docker, Deploy, Logs
  • A colour per button and an optional confirmation for risky ones
  • Run counter and an estimate of the typing time you saved
  • Multi-line commands; the panel is resizable and buttons wrap

SSH keys

Know which key opens which server

A local inventory of ~/.ssh, ~/.ssh/config and ssh-agent, tied to your consoles. The app never connects to servers to do it.

  • Type, strength score, passphrase, file permissions, loaded in agent or not
  • Which consoles and config hosts really use each key
  • Problems explained with advice: production on a key without passphrase, weak algorithm, open permissions, agent forwarding
  • Fix permissions or create an ED25519 key in one click

Production safety

Production looks like production

Mark a console as dangerous and you will never mistake it for staging: a red banner, a red frame around the terminal and a large watermark with your own label.

  • Your own label: PROD, CLIENT-DB, BILLING…
  • Confirmation before risky quick commands
  • Quit confirmation, so open sessions never close by accident
  • Dangerous consoles are marked in the tree and the recent list too

Small things that add up

Recent consoles

The last five consoles under the tree: back in one click, with open sessions and production marks visible.

Several instances

Open the same console twice — each copy gets its own sub-tab. Cmd+T on an open console.

Drag tabs around

Reorder terminal tabs and instance sub-tabs with the mouse; drag consoles between projects in the tree.

Clickable links

Cmd+click in the terminal, a plain click in wiki, AI chat and console notes. Only http, https and mailto open.

Mouse in htop and mc

Clicks, column sorting, F-key buttons and wheel scrolling reach programs on remote servers.

Copy the connection

A ready ssh command, user@host:port or a parameter list — passwords are never included.

Server list in Markdown

Export a workspace or project — hosts, ports, users, hosting provider — to a public .md. No secrets inside.

Encrypted backup

Export to .dchub: pick workspaces, wiki, AI chats and settings. Move everything to a new laptop in a minute.

Notes, icons, hosting

A note above the terminal, where the server lives, 29 icons and a colour to tell consoles apart.

Find anything

Cmd+P jumps to any console, Cmd+Shift+K searches every wiki page.

18 themes, 5 languages

9 dark and 9 light themes with matching terminal palettes. English, Русский, 中文, Français, Қазақша.

Lives in the tray

Close to tray, start at login, one instance only. Window size and panels are remembered.

Privacy

Your data stays yours

No account, no cloud sync, no telemetry. Everything lives on your computer.

Encrypted database

SQLite with SQLCipher (AES-256): consoles, SSH passwords, wiki and AI chats are encrypted on disk.

Password and auto-lock

A lock screen at start-up (Argon2id hash) and auto-lock after inactivity. Terminal sessions keep running underneath.

Safe export

Backups are encrypted with AES-256-GCM, optionally with your own password (PBKDF2, 100k iterations). The public .md export never contains secrets.

Local by design

The SSH audit only reads files on your machine. AI requests go out only to the provider you configure — or stay fully local with Ollama.
