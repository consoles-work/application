# Скилл autopost — публикация в Telegram-канал

Скилл для Claude Code: проект публикует посты (текст и картинки) в свой
Telegram-канал через сервис [koval-autopost](https://autopost.selll.ru/admin).
Сам скрипт `scripts/post.py` можно запускать и руками — из терминала, cron
или CI.

Как это устроено: скрипт отправляет пост в сервис по API-ключу, сервис
ставит его в очередь и публикует в канал ботом проекта. Токен бота у
скрипта не хранится — только ключ сервиса.

```
.claude/skills/autopost/
├── SKILL.md            — инструкция для Claude (когда и как публиковать)
├── README.md           — этот файл, для человека
├── config.env          — адрес сервиса, проект, ключ (секрет, не в git)
├── config.env.example  — образец config.env
├── .gitignore          — не даёт закоммитить config.env
└── scripts/post.py     — клиент: Python 3.10+, только стандартная библиотека
```

## Установка

Нужен Python 3.10 или новее (`python3 --version`) — больше ничего ставить не надо.

**Вариант 1 — архив с ключом (проще всего).** Админка → **Ключи** →
**Выпустить ключ** (выбрать проект) → **Скачать скилл (zip)**. В архиве
`config.env` уже заполнен. Распаковать в корень проекта, в `.claude/skills/`:

```bash
cd ~/work/мой-проект
mkdir -p .claude/skills
unzip ~/Downloads/autopost-news.zip -d .claude/skills/
# получится .claude/skills/autopost/
```

Ключ показывается один раз — скачать архив нужно сразу, на странице выпуска.

**Вариант 2 — шаблон с заглушкой.** Админка → **Проекты** → проект →
**скачать скилл с заглушкой**. После распаковки вписать ключ в `config.env`
вместо `kap_ЗАМЕНИТЬ` (ключ — в админке: Ключи → Выпустить).

**Вариант 3 — из каталога koval-autopost:**

```bash
make skill DEST=~/work/мой-проект PROJECT=news KEY=kap_…
```

Повторный запуск обновляет файлы скилла и **не затирает** уже заполненный
`config.env` — так же обновляют скилл до новой версии.

## Настройка

`config.env` рядом с `SKILL.md`:

```
AUTOPOST_URL=https://autopost.selll.ru
AUTOPOST_PROJECT=news
AUTOPOST_KEY=kap_…
```

| Переменная | Что |
|---|---|
| `AUTOPOST_URL` | Адрес сервиса (без `/api/v1`) |
| `AUTOPOST_PROJECT` | Адрес проекта в сервисе — видно в админке, «Проекты» |
| `AUTOPOST_KEY` | API-ключ `kap_…` с доступом к этому проекту |

Переменные окружения с теми же именами **важнее файла** — удобно для CI:

```bash
AUTOPOST_KEY=$SECRET_KEY python3 .claude/skills/autopost/scripts/post.py check
```

Ключ — секрет: `config.env` уже в `.gitignore` скилла, не коммитить и не
пересылать. Утёк — отозвать в админке (Ключи → Отозвать) и выпустить новый.

## Проверка

```bash
python3 .claude/skills/autopost/scripts/post.py check
```

```
проект: news — Новости
канал: Новости проекта https://t.me/news
бот: @news_bot
бот может публиковать — всё готово
```

Сервис при этом проверяет вживую: подходит ли токен бота, видит ли бот
канал, есть ли у него право публиковать. Если нет — скажет почему (см.
«Если что-то не так»).

## Публикация

Дальше `post.py` — это `python3 .claude/skills/autopost/scripts/post.py`.

```bash
# Текст прямо в команде
post.py send --text "**Вышла версия 2.0** — подробности на сайте"

# Текст из файла (Markdown), с картинкой
post.py send --text-file post.md --image cover.png

# Альбом: до 10 картинок — файлы и ссылки вперемешку
post.py send --text-file post.md --image 1.jpg --image 2.png --image https://example.com/3.jpg

# Только картинка, без текста
post.py send --image banner.webp

# Текст из другой программы
generate-news | post.py send --text-file -

# Отложить: через 2 часа или к точному времени (с поясом!)
post.py send --text-file post.md --at 2h
post.py send --text-file post.md --at 2026-11-20T09:00+03:00

# Без звука у подписчиков, без превью ссылок
post.py send --text-file post.md --silent --no-preview

# Посмотреть, что уйдёт, ничего не отправляя
post.py send --text-file post.md --image cover.png --dry-run
```

Ответ:

```
опубликован: https://t.me/news/123
id: 8cdd2f0a…
```

### Параметры send

| Параметр | Что |
|---|---|
| `--text "…"` | Текст поста |
| `--text-file путь` | Текст из файла; `-` — из stdin |
| `--image файл\|ссылка` | Картинка: файл JPEG/PNG/WEBP до 10 МБ или ссылка `https://…`. Можно до 10 раз |
| `--format markdown\|html\|text` | Разметка текста; по умолчанию — как настроено у проекта (обычно Markdown) |
| `--at 30m\|2h\|1d\|ISO` | Отложить; время ISO — обязательно с поясом (`+03:00` или `Z`) |
| `--silent` | Без звука у подписчиков |
| `--no-preview` | Не показывать превью ссылок |
| `--dry-run` | Только показать запрос |
| `--project имя` | Другой проект, не из `config.env` (ставится **перед** командой: `post.py --project other send …`) |

### Как писать текст

Обычный Markdown — сервис сам переведёт его в разметку Telegram,
экранировать ничего не нужно:

| Пишете | В канале |
|---|---|
| `**жирный**` | **жирный** |
| `*курсив*` или `_курсив_` | *курсив* (`snake_case` в словах не трогается) |
| `~~зачёркнутый~~` | ~~зачёркнутый~~ |
| `\|\|спойлер\|\|` | скрытый текст |
| `` `код` `` и блоки ```` ``` ```` | моноширинный |
| `[текст](https://…)` | ссылка |
| `> цитата` | цитата |
| `# Заголовок` | жирная строка |
| `- пункт` | • пункт |

Лимиты Telegram (считаются видимые символы, после разметки):

* текст — до **4096**;
* подпись к картинке — до **1024**. Длиннее — не ошибка: картинки выйдут
  отдельно, а текст следом вторым сообщением;
* картинок — до **10** (2 и больше — альбом).

## Другие команды

```bash
post.py status ID     # состояние поста и ссылка
post.py list          # последние 10 постов проекта (--limit 50 — больше)
post.py delete ID     # отложенный — отменить; опубликованный — удалить из канала
```

Telegram даёт удалять только посты моложе 48 часов.

## Коды выхода

| Код | Значит |
|---|---|
| `0` | Опубликован, запланирован, отменён или удалён |
| `1` | Ошибка: настройка, отказ сервиса, Telegram не принял пост. Текст — в stderr |
| `2` | Пост принят, но ещё в очереди (Telegram временно недоступен) — сервис повторит сам; проверить позже `post.py status ID` |

Обрыв связи скрипт повторяет сам (3 попытки) с тем же ключом
идемпотентности — второго поста не будет. А вот **второй запуск** `send` с
тем же текстом — это второй пост: если непонятно, вышел ли первый, сначала
`post.py list`.

## С Claude Code

Скилл подхватывается сам: достаточно попросить «опубликуй в канал новость
про …», «запланируй пост на завтра 9:00», «удали последний пост». Claude
напишет текст, покажет его и опубликует после подтверждения (если не
сказать явно «публикуй без показа»). Правила для Claude — в `SKILL.md`.

## Если что-то не так

| Сообщение | Что делать |
|---|---|
| `ошибка настройки: нет AUTOPOST_…` | Заполнить `config.env` (см. «Настройка») |
| `в config.env ключ-заглушка` | Вписать ключ из админки вместо `kap_ЗАМЕНИТЬ` |
| `ключ не подошёл или отозван [bad_key]` | Ключ отозван или с опечаткой — выпустить новый |
| `проект не найден [not_found]` | Неверный `AUTOPOST_PROJECT` или у ключа нет доступа к проекту |
| `бот не администратор канала` / `нет права «Публикация сообщений»` | В Telegram: канал → Администраторы → бот → включить право публикации; затем снова `check` |
| `токен не подошёл` | Токен бота перевыпущен — владельцу сервиса вписать новый в настройках проекта |
| `проект выключен [project_disabled]` | Проект выключен в админке |
| `… видимых символов, Telegram принимает до 4096 [text_too_long]` | Сократить текст или разбить на два поста |
| `не JPEG, PNG или WEBP [bad_image]` | Пересохранить картинку в JPEG/PNG (GIF и SVG Telegram как фото не примет) |
| `ошибка публикации [rejected]: … can't parse entities` | Битая разметка в `--format html` — поправить или писать в Markdown |
| `сервис недоступен` | Нет сети до `AUTOPOST_URL` или сервис лежит — `curl -I https://autopost.selll.ru/admin` |
| `ключ исчерпал … постов за сутки [daily_limit]` | У ключа суточный лимит — подождать или попросить поднять |

Полное описание API — `docs/api.md` в репозитории koval-autopost.
